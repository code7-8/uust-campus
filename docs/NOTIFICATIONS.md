# Проверка уведомлений

Изменения от 01.10.2026 требуют APK, собранного из обновлённых исходников. Обновление backend само по себе не меняет код Android на телефоне.

1. Откройте **Профиль → Уведомления**, включите напоминания и разрешите их в системном диалоге Android.
2. Нажмите **Проверить уведомление**. Это немедленное тестовое сообщение в том же канале «Пары и события». Оно проверяет разрешение и показ, но не точность фонового будильника.
3. Для фоновой проверки выберите напоминание **за 5 минут**, создайте встречу на 7–10 минут вперёд и нажмите **Я пойду** либо добавьте её в избранное. Убедитесь, что она появилась в ближайших напоминаниях. Время указывается для Уфы.
4. Если экран предлагает **Разрешить точные напоминания**, откройте настройку и разрешите «Будильники и напоминания». Вернитесь в приложение, затем сверните его и заблокируйте экран. Проверьте сообщение и переход к событию по нажатию.
5. Повторите с открытым приложением и обновлением афиши в момент напоминания. Должно прийти одно сообщение. Отмена участия/избранного до доставки или отключение категории должны отменять напоминание.

Android 13+ отдельно запрашивает разрешение на показ уведомлений. Доступ к точным будильникам также может быть выключен после новой установки. Без него система вправе задержать сигнал; сообщение после начала события уже не показывается. См. [разрешение уведомлений Android](https://developer.android.com/develop/ui/views/notifications/notification-permission) и [точные/неточные будильники](https://developer.android.com/develop/background-work/services/alarms).

Раньше обновление афиши удаляло напоминание, как только наступало `at`, даже если Android ещё не доставил сигнал. Теперь очередь сохраняет его до `start`, а Android и браузер помнят доставленные события. Повторное обновление или открытие приложения не создаёт дубль. Запись на встречу незадолго до начала тоже может дать напоминание сразу, если выбранное время уже наступило. Тихие часы продолжают исключать сообщения.

В браузере напоминания работают только при открытой странице. Android хранит очередь независимо от WebView и восстанавливает её после перезагрузки. Очередь отражает последние загруженные данные; изменения сервера требуют обновления приложения.

Автоматически проверены расчёт времени, поздняя доставка, повторная синхронизация, отмена, разрешения, повторная попытка при ошибке bridge и настройки в Chrome. Для успешного показа в браузерном тесте используется подмена OS API: headless Chrome сообщает `Notification.permission=denied` даже при разрешении через автоматизацию. Это проверяет вызов из интерфейса, а не видимость сообщения в системе. Java компилируется с API 35. Реальная фоновая доставка на Android в этой сессии не проверена: подключённых устройств и AVD нет.
